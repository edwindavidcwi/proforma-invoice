# Quiz Battle — audit checklist

What to check before each "final" build. The first section is automated (runs in
CI on every push); the rest needs a human, because scripts can't judge whether the
content matches the curriculum or whether a 6-year-old has fun.

## A. Automated (CI gates — already enforced)
These run on every push via `.github/workflows/build-apk.yml`. A red check blocks
the release.

- [x] **Boot + answer-cursor alignment** — `game/play/test_quiz_cursor.js`
- [x] **Cross-bank render, all 5 grades** — `game/play/play_capture.js`
- [x] **~1200 live renders + shuffle has no position bias** — `game/play/audit_render.js`
- [x] **Hit / miss / half-damage battle logic** — `game/play/audit_outcome.js`
- [x] **Context-aware music track selection** — `game/play/test_music.js`
- [x] **Independent answer-key recompute (math)** — `game/play/audit_facts.py`
- [x] **Content lint + data quality** — `game/pokered/audit_content.py`
      (charmap-safe, length limits, distinct options, valid indices, grade counts,
      and that the shipped data still matches the deterministic generator)

Run them all locally:
```
cd game/pokered && make pokered.gbc
cd ../play && for t in test_quiz_cursor play_capture audit_render audit_outcome test_music; do node $t.js ../pokered/pokered.gbc; done
python3 audit_facts.py ../pokered/pokered.gbc
python3 ../pokered/audit_content.py --report ../CONTENT_REPORT.md
```

## B. Teacher / curriculum review (human)
Skim `game/CONTENT_REPORT.md` (regenerated by the content audit). For each grade:

- [ ] **Grade-appropriate?** The skills match what this grade is actually taught.
- [ ] **Subject balance** looks reasonable (math-heavy is fine for early grades; see the table).
- [ ] **Distractors are plausible but clearly wrong** — not trivially eliminable and
      not accidentally correct. Watch for *repetitive* distractors (e.g. the same two
      wrong words on every question of a type) that let a child pattern-match instead of think.
- [ ] **Hints actually teach the method** ("Times before plus"), not just restate the answer.
- [ ] **No confusing wording** once squeezed to ≤18 chars.
- [ ] **Spelling/facts correct** (e.g. science/GK facts).

## C. Child play-test (watch them, don't ask them)
Sit beside the child for ~10 minutes and note, don't coach:

- [ ] Can they **read the question** (or does read-aloud cover it)? Read-aloud speaks
      *complete sentences*, no double-reads, decimals not split.
- [ ] Do they understand **what to do** without being told each time?
- [ ] A wrong answer feels **encouraging** (hint + retry), never punishing.
- [ ] They're **not getting stuck** (B can't escape a question; full heal after battles).
- [ ] **Difficulty feels right** — not so easy it's boring, not so hard they give up.
- [ ] They **want to keep playing** (the real success metric).
- [ ] Music/sound is **pleasant**, including at 4×/8× speed.

## D. On-device delivery smoke test (you, on real hardware)
CI builds these but can't run them on a real device:

- [ ] **Windows**: download `PokemonQuiz-Windows.exe` from the release, double-click,
      game opens (SmartScreen → *More info → Run anyway*).
- [ ] **Android**: install `PokemonQuiz.apk`, it launches and plays.
- [ ] **HTML**: open `PokemonQuiz.html` in a browser, no internet — works.
- [ ] **Save/Load**: multiple slots persist across close/reopen on each platform.
- [ ] **Speed 1×–8×**, fullscreen/immersive, and read-aloud all work on the device.
