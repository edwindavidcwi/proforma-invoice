# CLAUDE.md

Guidance for AI assistants (and humans) working in this repository.

## Project overview

A **proforma invoice generator for Cochin Wood Industries Private Limited** (a
plywood/wood-products manufacturer in Kerala, India). It is a single, editable
web page that a salesperson fills in on screen and then prints (or "saves to
PDF" via the browser print dialog) as a customer-facing proforma invoice.

The whole application is **one self-contained file: `index.html`**. There is no
build step, no package manager, no backend, and no test suite. Everything —
markup, styles, product catalog, and behavior — lives in that file.

## How to run / preview

There is nothing to build or install. To preview:

- Open `index.html` directly in a browser, **or**
- Serve the folder, e.g. `python3 -m http.server` and visit the page.

A network connection is needed for the CDN assets listed below; the page still
renders without them but loses Tailwind styling, the QR code, and the Poppins
font.

To produce the final document, use the **Print Invoice** button (or the
browser's print/⌘P), which is tuned for A4 output.

## Architecture & key conventions

### Single-file structure (`index.html`)

The file is organized top-to-bottom as:

1. **`<style>`** — custom CSS on top of Tailwind, including the print/A4 rules.
2. **`tailwind.config`** — inline Tailwind theme (brand color palette).
3. **`<body>` markup** — the visual invoice: header, customer/billing/shipping
   details, the products table, an optional transportation table, totals,
   signatures, bank details + UPI QR code, and terms & conditions.
4. **One big `<script>` inside a `DOMContentLoaded` handler** — all logic:
   product master data, totals, dynamic rows, address dropdowns, QR code, and
   date defaults.

### External dependencies (all via CDN — no local copies)

- **Tailwind CSS** — `https://cdn.tailwindcss.com` (utility classes + inline
  `tailwind.config`).
- **qrcodejs** — `https://cdnjs.cloudflare.com/.../qrcode.min.js`, used to
  render the UPI payment QR code into `#qrcode`.
- **Google Fonts: Poppins** — the page font.

When changing styling, prefer Tailwind utility classes inline on elements; only
drop into the `<style>` block for things Tailwind can't express cleanly
(print rules, `contenteditable` affordances, dropdown arrow removal).

### Brand colors (defined in `tailwind.config`)

| Token | Hex |
| --- | --- |
| `primary-dark` | `#004343` |
| `secondary-dark` | `#0a5e5e` |
| `primary-accent` | `#009a7b` |
| `secondary-accent` | `#11c99d` |
| `white-shade` | `#ffffff` |

Reuse these tokens (e.g. `text-primary-dark`, `bg-secondary-accent`) instead of
hardcoding new hex values, so the document stays on-brand.

### Editable fields

Most text fields are `contenteditable="true"` spans (e.g. `#invoiceNumber`,
`#clientName`, `#preparedBy`, `#orderSpecificTandC`) rather than `<input>`s.
Numeric/date/selection fields use real `<input>`/`<select>` elements. Both are
styled to look like plain text until hovered/focused, and are flattened (no
borders/background) in print via the `@media print` rules.

### Product catalog & auto-fill (the core domain logic)

The script builds an in-memory product master list and wires it to the
"Particulars" autocomplete:

- **`PRODUCTS`** — an object keyed by category (e.g. "Commercial Plywood",
  "Cochin Premium Marine Plywood", "Film Faced Shuttering Plywood",
  "Chequered Plywood", "Particle Board", etc.). Each value is an array of
  product records, some hardcoded and some generated by helper functions
  (`getFilmFacedShutteringEntries`, `getChequeredPlywoodEntries`) and IIFEs.
- Pricing helpers/constants: `getPrice(base, chemicalDipping)` adds ₹1.5 for
  chemical dipping; `DENSITY_STANDARD = 600`, `DENSITY_MARINE = 700`;
  `base_price_*` `Map`s keyed by `[thickness, weight].toString()`;
  `VALID_CONFIGS_*` define which thickness/weight combos are valid.
- **`formatLabel(cat, e)`** — builds the human-readable option string (and the
  lookup key) by joining category, grade, veneer, glue, color, GSM, mesh,
  weight, thickness, dimensions, and the `₹X/sqft` rate.
- **`ALL_PRODUCTS`** + **`labelToProduct`** (a `Map`) — flattened list and a
  label→record lookup. Labels populate the `<datalist id="product-list">`.
- When a user picks a product in a row's `.item-particulars` input, the
  `change` handler looks the label up in `labelToProduct` and auto-fills
  thickness, length, breadth, and rate, then recalculates.

If you add or reprice products, edit the `PRODUCTS` object (and the relevant
`base_price_*` maps / `VALID_CONFIGS_*` for the generated categories). Keep
record field names consistent (`Category`, `Grade`, `FaceVeneer`, `Glue`,
`Thickness_mm`, `Price_INR_per_sqft`, `Length_ft`, `Breadth_ft`, etc.) because
`formatLabel` and the auto-fill handler read those exact keys.

### Calculations

- **Product row**: `Qty(SqFt) = Len(ft) × Brd(ft) × Qty(Sht)`, then
  `Amount = SqFt × Rate/SqFt`. (Thickness is informational; it does not enter
  the area/amount math.)
- **Transportation row**: `Amount = Weight(Tonne) × Rate/Tonne`.
  (Distance is informational only.)
- Each table has its own GST dropdown (`0.1%`, `5%`, `12%`, `18%` default,
  `28%`). `updateTotals()` recomputes both subtotals, both taxes, and the
  **Grand Total** = product subtotal + product tax + transport subtotal +
  transport tax. Call `updateTotals()` after any change that affects amounts.
- All money is rendered with `formatCurrency()` as `₹X.XX`. Currency is INR
  only.

### Dynamic rows

- `createItemRow(sno)` / `createTransportationRow(sno)` build `<tr>` markup and
  attach the input/remove listeners. Add buttons (`#addItemBtn`,
  `#addTransportationItemBtn`) append rows; `updateSno(tableId)` renumbers the
  S.No column after add/remove.
- The products table always keeps **at least one row**. The transportation
  table is hidden by default behind the **Add Transportation** button; removing
  its last row hides the whole section again.

### Address dropdowns

`statesAndDistricts` is a large object mapping every Indian state/UT to its
districts. `populateStates` / `populateDistricts` cascade the district dropdown
off the selected state for both billing and shipping; **Copy from Billing**
mirrors billing → shipping.

### Company / payment constants (hardcoded in markup)

GSTIN `32AAJCC9689H1Z5`, ICICI Bank account, and the UPI ID
`cochinwoodindustriesprivatelimited.ibz@icici` (also encoded into the QR code)
are baked into the HTML. Update them in the markup **and** in the
`qrCodeData`/`upiId` variables in the script if banking details change.

### Defaults on load

Invoice date is set to today; "Valid Till" is today + 15 days; the P.I. number
is auto-generated as `PI-CWI-DDMMYY-001` (the `-001` suffix is a static
placeholder, not a real sequence).

## Known gaps / things to watch

- **`#saveToSheetBtn` ("Save to Google Sheet") has no event listener** — it is
  a non-functional placeholder. There is no persistence/backend; refreshing the
  page loses all entered data. Don't assume saving works.
- **No automated tests, linting, or CI.** Verify changes by opening the page
  and exercising the flow (add rows, pick products, toggle GST, change states,
  print preview).
- **Print is a first-class output.** Any layout change must be checked in print
  preview (A4) as well as on screen — the `@media print` block deliberately
  hides `.no-print` controls, flattens form fields, forces a page break before
  the terms section (`#terms-and-footer-page`), and fixes the QR size.

## Workflow & git conventions

- **Develop on the branch you were assigned** for the task; create it locally
  if needed. Do not push to `main` without explicit permission.
- Commit with clear, descriptive messages. Existing history is small and
  feature-focused (e.g. "Add product master data and auto-fill functionality
  for invoice items").
- Push with `git push -u origin <branch-name>`, then open a **draft PR** if one
  doesn't already exist.
- Because there is no build/test tooling, the review signal is the diff plus a
  manual check in the browser (including print preview).
